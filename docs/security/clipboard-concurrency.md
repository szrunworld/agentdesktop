# 进程内剪贴板串行化

关联：#183、#213；适用于系统剪贴板和命名剪贴板。

## 规则

同一进程的所有 NSPasteboard 操作必须由一个共同的串行化机制协调。创建、清空、读取、写入、释放剪贴板均在同一机制内完成；使用不同名称不构成隔离。不能靠重试或扩大超时处理并发死锁。

串行化必须避免在协作线程或主线程上同步等待需要这些线程完成的工作。等待租约时须有截止时间，并响应取消；取消之后不能继续输入。不同进程之间的剪贴板租约仍然需要保留。

## 当前边界

- iPhone 粘贴事务在 ClipboardLease 内执行；租约同时限制本进程和其他进程。
- 主窗口复制按钮在主线程操作系统剪贴板。
- 当前 Runtime/host 不链接 iPhone 输入路径；RuntimeClipboardPolicyTests 维护这一边界。两个路径目前不会在同一进程并发执行。
- 不把实验中串行运行没有死锁解释为 Apple 对剪贴板实现的保证。

## 合并两个路径之前

如果将 iPhone 输入路径链接进主窗口进程，必须先让主窗口复制按钮和 iPhone 粘贴使用同一个进程内协调器，覆盖命名剪贴板，并保留跨进程租约。不能只给粘贴路径加锁。

该改动需要确定性回归：复制与粘贴同时请求时只允许一个事务访问剪贴板；取消和超时结束等待；未知粘贴结果不再次发送输入。真实 pboard 长时间测试作为补充，不能替代上述回归，也不能声称已经证明永不死锁。
