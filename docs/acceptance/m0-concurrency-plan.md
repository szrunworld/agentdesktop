# M0 验收方案：两个 desktop 与宿主同时工作

目标：证明在同一台 Mac 上，两个 desktop 各自接收独立输入并发运行，用户同时正常使用宿主，停止与故障互不干扰。这是首发的关键出口条件（产品基线规则 2）。

## 测试组合（执行时填写）

| 项 | 值 |
| --- | --- |
| 系统版本 | |
| 执行后端 | Agent Desktop 0.1.0-dev 产品宿主或测试副本；引擎提交 |
| Desktop A | BOSS直聘：网页（浏览器与版本）还是客户端（版本） |
| Desktop B | 原生微信（版本） |
| 宿主 | 用户在编辑器里持续打字并移动鼠标 |
| 调用端 | A 由 BOSS Agent 驱动，B 由第二个独立调用端（CLI 脚本或另一个 Agent）驱动 |

## 验收表

| 验证项 | 要看到的实际结果 | 证据 |
| --- | --- | --- |
| 三个同时存在的输入流 | BOSS Agent、第二个调用端、用户宿主操作同时发生，不是轮流演示 | 录屏 + 带 desktopId、请求关联 id 和时间戳的日志，时间轴上三者重叠 |
| 输入正确性 | 点击、中文输入、滚动、快捷键、菜单、弹窗、拖动逐项记录支持或失败 | 每项一条日志与截图 |
| 宿主仍可用 | 用户打字和移动鼠标正常；焦点、按键修饰状态、剪贴板不被污染 | 用户编辑器内容与预期一致；剪贴板前后对比 |
| 停止与故障 | 停止或卡住 A，B 继续；A 的旧控制者和排队动作不能再输入 | 停止 A 后对 A 的动作被拒绝并说明原因，B 的动作继续有回执 |
| 目标变化 | 窗口重建、绑定或几何变化时拒绝无效动作并返回明确原因 | 对已关闭窗口的动作返回 window_lost 类错误 |
| 证据 | 录屏结合日志，能检查实际并发与动作落点 | 归档到 docs/acceptance/m0-<日期>/ |

## 分两步执行

1. **中性预演（不需要业务账号）**：两个或三个 desktop 上放计算器与文本编辑器，脚本并发驱动点击与中文输入，宿主侧由用户打字。用于先暴露引擎层的焦点与输入路由问题。记录见 m0-neutral-<日期>.md。
2. **正式组合**：Desktop A BOSS直聘，Desktop B 原生微信，按上表逐项记录。需要用户登录两个账号并在宿主上操作，由执行 agent 驱动脚本并收集证据。

## 判定

原生后端通过：继续 M1。失败原因是共享焦点或其他结构性约束：调整后端（例如按应用进程投递键盘事件的方式、修饰键状态隔离），不用全局排队掩盖。
