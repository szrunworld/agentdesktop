# 测试不碰用户屏幕：叠加层、启动挪窗与截图期间的指示器（2026-10-08）

UI 代理在 U1b-1 测试副本里报告了两个问题，都违反“测试不碰用户屏幕”：
1. 主显示器上出现属于测试副本的透明窗口，层级 25，坐标 (0,280)，尺寸 1280×800；
2. `app launch --new-instance` 报 “the app refused to move its window”，窗口留在主显示器上。

本机重启后真机复测时，又发现第三个问题：G0 的截图前后复核每次都失败。

## 原因与修改

| 问题 | 原因 | 修改 |
| --- | --- | --- |
| 叠加层落到主显示器 | `AgentCursorOverlay` 初始化时无条件 `orderFrontRegardless`。如果对应虚拟显示器的 NSScreen 还没出现或已经消失，`fitToDisplay` 什么也不做，屏幕大小的透明窗口就留在当前所在的显示器上，通常是主屏 | 只有窗口确实在自己的显示器上才显示；找不到显示器或落在别的显示器上就 `orderOut`；监听屏幕参数变化，每次都重新核对 |
| 启动后挪窗失败，窗口留在主屏 | 窗口刚出现时往往还不接受辅助功能的移动；只尝试一次，失败后只报错，App 继续运行 | 3 秒内每 0.25 s 重试；仍失败就结束这个刚为 Agent 启动的进程（先 terminate，1 s 后 forceTerminate），并在报错里说明 |
| 截图前后的复核总失败 | 复核的指纹包含整块屏上的所有窗口，而每次截图时菜单栏的录屏指示器（约 10×18）都会出现 | 指纹只取与绑定窗口重叠的窗口（以及绑定窗口自身）。别处的变化不影响截到的内容；同进程前置窗口的检查不变。拒绝信息里附带前后指纹，方便排查 |

剩余风险：App 刚启动的窗口出现在主屏、到被挪走之间仍有短暂闪现，这是先启动再移动的方式固有的，本次没有消除。

## 验证

- `swift test` 416 项、`swift test --package-path engine` 133 项，退出码均为 0。新增测试 `aWindowAppearingElsewhereOnTheScreenDoesNotVoidTheObservation`。
- 真机（测试副本 /tmp/adt-ov，用 CGWindowList 列出宿主进程和计算器的全部窗口）：

| 时机 | 宿主窗口 |
| --- | --- |
| 创建 Desktop 后 | 层级 25 的叠加层，范围 (1920,0,1920,1080)，**在虚拟显示器上**，不在主屏 |
| 启动计算器、连续 observe 3 次、点击 7 | 3 次 observe 都成功（截图、AX 都完整，27 个元素），点击已送达；叠加层仍在虚拟显示器；计算器窗口在虚拟显示器 |
| 销毁 Desktop 后 | 叠加层 onscreen=false，**没有出现在任何显示器上** |

修复前的同一构建（只改了叠加层）复现了截图复核的问题：拒绝信息显示截图后多出窗口 414，位置 (3697,3)，尺寸 10×18。

“refused to move” 的路径没能在真机上触发，由代码审读覆盖。
清理：退出计算器，销毁 Desktop，停止副本，删除目录；最后确认没有残留的宿主进程。
