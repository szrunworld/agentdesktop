# Runtime 审计持久性回归（2026-10-08）

修复两个 review 问题：投递标记或结果写入失败被忽略，以及同一个 Run 并发分配事件序号时撞号丢记录。

## 行为

- RequestLedger 的投递标记与结果写入传播错误；结果写入失败也会唤醒等待同键请求的调用方。
- 输入前必须成功保存投递标记与 Run 投递事件。失败返回 `audit_unavailable`，`notSent: true`，不调用平台输入。
- 审计写入失败锁定输入准入并停止活跃 Run；不能通过 `runtime.enableInput` 绕过，需修复存储后重启。读取诊断仍可用；已存请求结果仍可按原键读取，未存结果不会重放输入。
- 已投递动作的结果写入失败不返回成功或 `notSent: true`。投递标记保持落盘，重启后请求恢复为 unknown。
- RunStore 的写入错误记录为持久的健康失败状态，Runtime 检查该状态；不能吞错后继续发送输入。
- SQLite 事务在同一个递归锁内执行完整 body；事件序号查询和插入在一个事务中完成。

## 验证

在隔离 worktree 中执行根包 `swift test -j 4`（使用指定 scratch-path）：退出码 0，408 项通过。使用 SQLite trigger 注入失败和 FakePlatform 统计输入，不操作用户窗口。

| 回归 | 结果 |
| --- | --- |
| 投递标记写入失败 | `audit_unavailable`、`notSent: true`、平台输入 0；活跃 Run 归零；准入 stopped；恢复数据库后也不能直接开启输入 |
| 投递后结果写入失败 | 平台输入 1；响应不声明未发送；同键请求返回未知且不再输入；重启后账本为 unknown |
| Run 投递事件写入失败 | 平台输入 0；返回明确未发送；停止准入 |
| 500 次并发事件写入 | 501 条（含 run.started），序号 1–501 连续，500 个载荷索引各出现一次；重开数据库无丢失 |
